## فاز ۱: تحلیل واژگانی (`lexer.py`)

یک **اسکنر دستی** (بدون ابزارهایی مثل Lex) که مثل یک ماشین حالت متناهی (DFA) کار می‌کند: با دیدن کاراکتر اول تصمیم می‌گیرد چه توکنی در حال خواندن است.

| کاراکتر اول | حالت |
|---|---|
| رقم (لاتین یا فارسی) | عدد صحیح/اعشاری |
| حرف یا `_` | شناسه یا کلمهٔ کلیدی (با جدول `KEYWORDS`) |
| `"` | رشته (با درون‌یابی) |
| `//` یا `/*` | توضیح (نادیده گرفته می‌شود) |
| سایر | عملگر با قاعدهٔ **بلندترین تطابق** (`..=` قبل از `..` قبل از `.`) |

**نکات جالب:**
- `1..5` باید `INT DOTDOT INT` باشد نه `FLOAT(1.) ...`، پس عدد فقط وقتی اعشاری است که بعد از `.` رقم بیاید (پیش‌نگری دوکاراکتری).
- هر توکن پرچم `nl_before` دارد: «آیا قبل از من خط جدید بوده؟». پارسر با این پرچم پایان دستور را بدون `;` تشخیص می‌دهد.
- **درون‌یابی رشته:** متن داخل `{...}` به‌صورت خام نگه داشته می‌شود. پارسر بعداً با یک Lexer و Parser جدید (**تجزیهٔ بازگشتی**) آن را به عبارت تبدیل می‌کند. موقعیت سطر/ستون حفظ می‌شود تا پیام خطا دقیق باشد.

نمایش: `python -m nova tokens examples/counter.nova`

## فاز ۲: تحلیل نحوی (`parser.py`)

**پارسر نزولی بازگشتی (Recursive Descent)**، به ازای هر قاعدهٔ گرامر یک تابع:

```
expression → or_expr → and_expr → not_expr → comparison
           → additive → multiplicative → unary → postfix → primary
```
اولویت عملگرها مستقیماً از **ترتیب فراخوانی** این توابع می‌آید: تابع پایین‌تر زودتر گره می‌سازد، پس عملگرش اولویت بالاتری دارد. شرکت‌پذیری چپ با حلقهٔ `while` پیاده شده است (نه بازگشت) تا `a - b - c` به‌صورت `(a - b) - c` ساخته شود.

**بهینه‌سازی کوچک:** `-5` در همان پارسر به لیترال `IntLit(-5)` تا می‌شود (**Constant Folding**).

**پیام‌های خطای هوشمند:** مثلاً `1 < x < 5` پیام `comparisons cannot be chained; use 'and'` می‌دهد.

نمایش: `python -m nova ast file.nova`

## فاز ۳: تحلیل معنایی (`checker.py`)

۱. **گذر اول:** امضای همهٔ توابع و نام همهٔ صفحه‌ها جمع می‌شود. به همین دلیل ارجاع پیش‌رو و بازگشت متقابل ممکن است.

۲. **گذر دوم:** پیمایش کل درخت با یک **جدول نماد** به شکل پشته‌ای از دیکشنری‌ها:
```
scopes = [ {سراسری}, {پارامترهای تابع}, {بلوک if}, {بدنهٔ حلقه} ]
         push() هنگام ورود به بلوک        pop() هنگام خروج
```
هر نماد این اطلاعات را دارد: نوع، قابل تغییر بودن، و نوع نماد (global/local/param/loop/state).

۳. **قواعد نوع** (نمونه):
```
Γ ⊢ e1 : Int   Γ ⊢ e2 : Int          Γ ⊢ e1 : String  یا  Γ ⊢ e2 : String
────────────────────────────          ─────────────────────────────────────
     Γ ⊢ e1 + e2 : Int                         Γ ⊢ e1 + e2 : String

Γ ⊢ e1 : Int   Γ ⊢ e2 : Float              Γ ⊢ c : Bool   Γ ⊢ S1   Γ ⊢ S2
───────────────────────────────            ───────────────────────────────
     Γ ⊢ e1 + e2 : Float                      Γ ⊢ if c { S1 } else { S2 }
```

۴. **حاشیه‌نویسی AST:** روی هر عبارت `ty` (نوع) و در صورت نیاز `coerce_to` نوشته می‌شود. مثلاً در `let x: Float = 1`، گره `1` علامت `coerce_to = Float` می‌گیرد. مفسر آن را به `1.0` و تولیدکنندهٔ کد آن را به `1.0` یا `x.toDouble()` تبدیل می‌کند.

۵. **تحلیل جریان کنترل:** تابع `returns()` بررسی می‌کند آیا همهٔ مسیرها به `return` می‌رسند:
```
returns(return e)           = true
returns({ s1; ...; sn })    = returns(s1) or ... or returns(sn)
returns(if c {A} else {B})  = returns(A) and returns(B)
returns(سایر)               = false
```

۶. **بررسی‌های وابسته به متن:** متغیرهای `in_action`، `loop_depth` و `fun_ret` مشخص می‌کنند در کجای برنامه هستیم.

## فاز ۴الف: مفسر (`interpreter.py`) و شبیه‌ساز (`simulator.py`)

- **مفسر درخت‌پیما:** هر نوع گره یک شاخه در `eval` یا `exec` دارد.
- **محیط (Environment):** زنجیره‌ای از دیکشنری‌ها که هر کدام به محیط والد اشاره می‌کند. توابع در محیطی اجرا می‌شوند که والدش محیط سراسری است، یعنی **حوزهٔ ایستا** و نه پویا.
- **جریان کنترل غیرمحلی:** `return`، `break` و `continue` با استثناهای پایتون (`ReturnSignal` و ...) پیاده شده‌اند.
- **شبیه‌ساز:** درخت UI را با مقادیر فعلی state ارزیابی می‌کند (مثل Compose)، به عناصر تعاملی شماره می‌دهد و بعد از هر رویداد دوباره رسم می‌کند. بلوک دکمه در محیطی اجرا می‌شود که متغیر حلقهٔ UI در آن ثبت شده است (**Closure**).

```
$ python -m nova sim examples/counter.nova
+------------ شمارنده > Main ------------+
| == شمارنده ==
| مقدار فعلی: 0
| [1: −]   [2: +]
| [3: صفر کن]
+----------------------------------------+
> 2
```

## فاز ۴ب: تولید کد (`codegen_kotlin.py`)

| Nova | Kotlin |
|---|---|
| `let x = 5` | `val x: Int = 5` |
| `var xs: List<Float> = [1, 2]` | `var xs: List<Double> = listOf<Double>(1.0, 2.0)` |
| `for i in 0..n` | `for (i in 0 until n)` |
| `for i in 1..=n` | `for (i in 1..n)` |
| `"سلام {name}"` | `"سلام ${name}"` |
| `a and not b` | `a && !b` |
| `len(xs)` / `len(s)` | `xs.size` / `s.length` |
| `screen Main { ... }` | `@Composable fun MainScreen(...)` |
| `state n = 0` | `var n by rememberSaveable { mutableStateOf<Int>(0) }` |
| `button("+") { n += 1 }` | `Button(onClick = { n += 1 }) { Text(text = "+") }` |

**چالش‌ها و راه‌حل‌ها:**
1. **اولویت عملگرها:** هر عبارت همراه با «سطح اولویت» خودش تولید می‌شود و فقط وقتی پرانتز می‌گیرد که اولویتش از اولویت لازم کمتر باشد. پس `(1 + 2) * 3` پرانتز دارد ولی `1 + 2 * 3` ندارد.
2. **تداخل نام:** اگر کاربر متغیری به اسم `val` یا `when` (کلمهٔ کلیدی Kotlin) بسازد، نامش با بک‌تیک (`` `val` ``) نوشته می‌شود. اگر اسمش `Text` یا `Button` باشد (که در کد تولیدی استفاده می‌شوند)، به `Text_` تغییر می‌کند.
3. **تفاوت انواع:** در Kotlin تبدیل ضمنی Int به Double وجود ندارد (`val d: Double = 1` خطاست)، پس کامپایلر خودش `.toDouble()` یا `1.0` درج می‌کند.
4. **ناوبری:** یک پشته از نام صفحه‌ها (`mutableStateListOf`) به‌همراه `SaveableStateHolder` تا state هر صفحه حفظ شود، و `BackHandler` برای دکمهٔ Back گوشی.
